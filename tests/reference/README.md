# Remote regression inputs

The four compiler, topology and HTTP JSON corpora preserve the original verified response bytes. The station corpus preserves all recorded route observations across four scenarios. Its owner field is the index of a synthetic owner. Each verification run substitutes a fresh identity in both the database and the recorded requests. The pin file records SHA-256 for each corpus and the CIRNET Lab source revisions that produced them. [Corpus provenance](corpus/provenance.json)

The database seeders reproduce each historical migration boundary and construct fresh SQLite and optional PostgreSQL databases. Only test processes load the supporting Python modules. The modules under `seed_source/app` originate from CIRNET Lab's cirnet-remote, under `migration/python-reference/services/api/app`. The original tracked `services/api/app/db` supplied the database schema. The authentication configuration is reduced to fixture settings. The old simulator import alias has been removed. The Python modules and schema resources under `seed_source/contracts` originate from CIRNET Lab's cirnet-contracts, under `migration/python-reference/contracts` and `contracts`. The files were selected from the dependencies exercised by the seeders. The corresponding source revisions are recorded in the provenance file. The source and fixtures remain under the repository's GNU General Public License version 3. [License](../../LICENSE)

Generated sessions, password hashes, expirations, database URLs and IDs belong to the current run. The test peer generates Python RPC bindings from the selected Contracts Next schema. The Rust assertions compare against the fixed recorded outputs. The optional native-peer checks additionally hash the packaged Hardware and worker bytes against the independently selected manifest.
